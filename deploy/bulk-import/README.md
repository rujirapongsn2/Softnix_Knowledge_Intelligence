# นำเข้าเอกสารจำนวนมากพร้อมไฟล์อ้างอิง

`import_documents.py` ส่งเอกสาร Markdown พร้อมไฟล์อ้างอิงผ่าน Ingest API ใช้แค่ Python มาตรฐาน รันบนเครื่องใดก็ได้ที่เรียก API ถึง

## เตรียมไฟล์

วางคู่ไฟล์ที่ชื่อเหมือนกันไว้ในโฟลเดอร์เดียว:

```
corpus/
  law-0001.md     เอกสารหลัก ถูกนำไปค้นหา
  law-0001.pdf    ไฟล์อ้างอิง เก็บเป็นหลักฐานและให้ดาวน์โหลด ไม่ถูกประมวลผล
  law-0002.md     ไม่มีไฟล์อ้างอิงก็นำเข้าได้
```

ไฟล์อ้างอิงเป็น `.pdf`, `.docx`, `.doc`, `.xlsx`, `.xls` หรือ `.txt` ได้ ผูกได้เอกสารละหนึ่งไฟล์ และขนาดไม่เกิน `MAX_FILE_SIZE_MB` (100 MB)

## รัน

สร้าง ingest token ของ KB ปลายทาง (หน้า API Keys แบบ Ingest หรือ `POST /api/v1/tokens` พร้อม `allowed_scopes: ["documents:write"]`)
ค่าเริ่มต้นของ ingest token (600 requests/min, 10 พร้อมกัน) เพียงพอสำหรับ script นี้

```sh
INGEST_TOKEN=<token> python3 deploy/bulk-import/import_documents.py \
  --api http://127.0.0.1:8001 --kb <KB_ID> --dir corpus --document-type-id <DOCUMENT_TYPE_ID> --wait
```

`--document-type-id` คือประเภทเอกสารของ KB ที่กำหนดฟิลด์ให้ระบบสกัด ดู id ได้จาก `GET /api/v1/ingest/knowledge-bases/<KB_ID>/document-types`
ถ้าไม่ใส่ เอกสารจะเป็นประเภท general และระบบจะไม่สกัด metadata

script ทำงานตามลำดับนี้:

1. ส่งไฟล์ `.md` ทีละ 20 ไฟล์ แล้วเก็บ `document_id` ของแต่ละไฟล์
2. ผูกไฟล์อ้างอิงกับเอกสาร ทีละไฟล์ ผูกได้ทันทีโดยไม่ต้องรอประมวลผลเสร็จ
3. ถ้าใส่ `--wait` จะรอจนทุกเอกสารประมวลผลเสร็จ แล้วสรุปจำนวนตามสถานะ รายชื่อเอกสารที่ล้ม และไฟล์ที่ถูกปฏิเสธ

## รันซ้ำได้

ความคืบหน้าถูกบันทึกใน `corpus/.import-state.json` ถ้า script หยุดกลางทาง ให้รันคำสั่งเดิมอีกครั้ง:

- เอกสารที่ส่งแล้วจะไม่ถูกส่งซ้ำ ส่วนไฟล์อ้างอิงที่ยังไม่ได้ผูก จะถูกผูกต่อ
- ถ้าส่งไปแล้วแต่ไม่ได้รับคำตอบกลับ API จะตอบ `FILE_DUPLICATE` แล้ว script จะหา `document_id` เดิมจากชื่อไฟล์ใน KB ให้เอง
- ถ้าโดน rate limit (429) หรือ API ไม่ตอบชั่วคราว (502–504) script จะรอนานขึ้นทีละเท่า ไม่น้อยกว่า `Retry-After` ที่ server บอก แล้วส่งใหม่

เมื่อเครดิตของผู้ให้บริการ AI หมดระหว่างนำเข้า งานจะรออยู่ในคิว และทำต่อเองหลังเติมเครดิต ไม่ต้องรัน script ใหม่
ดูสถานะการพักได้ที่ `services.provider_holds` ของ `GET /api/v1/system/dashboard`

## ผลจำลอง (2026-10-20, เครื่อง dev)

นำเข้าเอกสารกฎหมาย 12 ไฟล์ `.md` (ราว 104k ตัวอักษร) คู่กับ PDF อ้างอิง 11 ไฟล์ และมี PDF เสีย 1 ไฟล์ที่ใส่ไว้ทดสอบ:

- ทั้ง 12 ฉบับประมวลผลเสร็จ ผูกไฟล์อ้างอิงได้ 10 ไฟล์ และ PDF เสียถูกรายงานว่า `REFERENCE_FILE_INVALID`
- รันซ้ำแล้วไม่ส่งไฟล์ใดซ้ำ
- ลบ `document_id` ของเอกสารหนึ่งออกจาก state เพื่อจำลองคำตอบที่หายไป script หา id เดิมจากชื่อไฟล์ได้ถูกต้อง
- ผลค้นหามี `reference_file.download_url` ของ PDF
- ค่า LLM รวมคำถามที่ใช้ตรวจอยู่ที่ $0.12

ก่อนนำเข้าจริง ให้นำร่องประมาณ 200 คู่จากชุดจริงใน KB แยก แล้วใช้ค่าใช้จ่ายต่อเอกสารและเวลาที่วัดได้ ประเมินงบและเวลาของทั้งชุด
